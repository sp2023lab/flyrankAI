The problem

Static interview question lists do not adapt to the user and often produce feedback disconnected from the candidate’s actual projects. The goal was one job done well: run a short interview, use personal project notes for grounding, evaluate each answer and choose the next question based on evidence.

My role

I wrote the FL-06 design specification and implemented the FL-07 command-line MVP. I defined the workflow, four tool responsibilities, structured models, local data format, scoring rubric, guardrails and pre-build evaluation cases.

How it works

The user selects a topic, difficulty and question count. The agent reads previous progress, retrieves relevant excerpts from local CV and project notes, asks one question and waits for an answer. It then returns a structured evaluation with a 1–5 score and next action. Results are saved to JSON and the final tool produces a session report.

Technical decisions

The MVP is a single-agent CLI because a web interface and multi-agent orchestration would add complexity without proving the core workflow. The project includes a deterministic mock provider for no-cost testing and a live provider for the final run. Local files are read-only; the only write target is the dedicated progress store.

Testing and evaluation

Pre-build cases cover an incomplete REST definition, a strong WebSocket answer, project-grounded questioning, an unsupported Kubernetes claim, an incomplete STAR answer, adaptive database questioning and correct five-question termination. Automated tests exercise retrieval, progress persistence and end-to-end completion.

Outcome

The MVP completes the full loop without mid-run file editing: request, retrieval, question, answer, evaluation, saved progress and final report. It demonstrates a real file connection and persistent state while remaining small enough to understand and explain.

Limitations and next steps

Keyword-based retrieval is adequate for the small local document collection but will not scale as well as semantic retrieval. Scores still depend on model judgement, and the CLI is intentionally plain. Future work would compare scoring consistency, add job-description targeting and improve evidence shown alongside each score.
